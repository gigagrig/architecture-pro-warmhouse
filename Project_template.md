# **Задание 6. Разработка MVP**

Необходимо создать новые микросервисы и обеспечить их интеграции с существующим монолитом для плавного перехода к микросервисной архитектуре. 

### **Что сделано**

1. Создан новый микросервис **Telemetry Service** на Go. Он подписан на MQTT топик `sensors/+/telemetry` и сохраняет данные в общую базу данных Postgres в таблицу `telemetry`.
2. Создан микросервис-симулятор **Humidity-Temperature-Sensors-Service**, который имитирует работу реальных датчиков, публикуя данные в MQTT брокер Mosquitto.
3. Существующий монолит **SmartHome** интегрирован в новую архитектуру. В него добавлен эндпоинт `/api/v1/telemetry`, который позволяет просматривать данные, собранные новым микросервисом телеметрии.
4. Разработан **API Gateway**, выступающий единой точкой входа (Edge Layer) и маршрутизирующий запросы к новым микросервисам и старому монолиту.
5. Создан **Device Service** (Core Business Service) для управления устройствами, сохраняющий данные в новую таблицу `devices` в PostgreSQL.
6. Разработан **Command Service** (Data & Action Service), предоставляющий REST API для отправки управляющих команд в MQTT.
7. Добавлен **Scenario Service** — простейший движок правил (Rules Engine), который подписывается на телеметрию и, при падении температуры ниже 22 градусов, отправляет команду через Command Service.
8. Подготовлен каркас **Auth & ACL Service** для обеспечения вебхуков плагину `mosquitto-go-auth` (Mosquitto).
9. Все микросервисы оркеструются через обновленный `apps/docker-compose.yml`, где API Gateway занял порт 8080 (ранее порт монолита). Инициализация базы данных дополнена созданием всех необходимых таблиц.
